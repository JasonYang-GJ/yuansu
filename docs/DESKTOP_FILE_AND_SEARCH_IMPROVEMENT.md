## 实现与根因

当前网易云的 `OrpheusBrowserHost` 内含 CEF renderer。原始只读 UIA 探针获得 0 个 Edit；激活本窗口的本机辅助功能对象后，UIA 暴露两个歌曲占位名称输入框，其 native IA2 uniqueID 相同，且 `tag:input;text-input-type:search` 明确表达搜索语义。

实现通过该 renderer 自己的 `accHitTest` 将 UIA 输入框映射回原生对象，不使用全桌面 AccessibleObjectFromPoint。匹配同时要求原生角色、矩形、名称、原生 provider window 的归属和唯一 ID；每次回读重查。IA2 属性解析支持转义并拒绝重复键，不能把任意 CSS class 中伪造的字段当作搜索权限。UIA 代理只有原生身份相同、快照内容一致时才能合并；不同搜索框仍拒绝猜测。

首次主窗口代理发现约 17.3 秒；改为直接查询精确 renderer 根后，本机只读样本为约 7.8 秒并返回 1 个搜索对象。此数据只反映当前机器与当前页面，不是普遍速度承诺。平台 COM 调用仍可能阻塞，取消在控制权返回后及写入/提交前检查，不能据此声称可立即中断所有第三方 COM 调用。

接口依据：[Chromium 辅助功能机制](https://www.chromium.org/developers/design-documents/accessibility/)、[IAccessible2 元数据与对象身份](https://accessibility.linuxfoundation.org/a11yspecs/ia2/docs/html/interface_i_accessible2.html)。没有采用屏幕阅读器全局开关、启动参数、注册表修改或调试端口。

桌面文件解析只检查名称和文件元数据。名字唯一不等于允许执行程序，自动解析仅接受所列文档/媒体类型；既有显式文件选择能力保持原合同。发现路径在原 Turn 保存，防止确认时重新按名字找到另一个文件。首次确认到续接之间变化则拒绝；已启动后文件是否加载完成仍未验证。

## 后续：应用称呼与实际桌面入口修复

用户随后报告“打开我的网易云”失败，并确认使用桌面“元枢”快捷方式。核验发现：该快捷方式仍指向早期已安装程序，上一轮隔离候选数据库没有任何用户 Turn。因此此前源码修复没有进入用户平常的启动入口，不能把隔离启动成功当成已交付。

应用目录原本已有“网易云”短名，但没有处理“我的”“我电脑上的”等前缀。新实现先保留完整登记名称的优先级，再仅移除限定的句首所属表达，沿用原有别名与唯一目标解析。“给我打开”“麻烦你打开”“帮我把…打开”进入本地确定性规划，不依赖聊天模型猜测。路径、脚本、命令参数和提权检查不变，普通能力问句与否定句不取得执行权限。

- 失败复现：4 个所属称呼解析失败，3 个口语表达落入 Conversation。首次测试还暴露 1 个测试自身重复创建文件的问题，已修正夹具；原始红色 TRX 保留。
- 修复后 Release 回归：AI.Core 170/170、Skills.Windows 162/162、DesktopHost 384/384，共 716/716，无失败或跳过。此数字仅指本次相关模块，不是整个解决方案。
