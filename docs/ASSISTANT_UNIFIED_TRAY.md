# 元枢统一托盘入口

> 本文记录完整合并之前的托盘阶段。后续用户已授权统一仓库、构建和安装，当前实现以 [合并范围](UNIFIED_PRODUCT_PLAN.md) 和 [统一构建与更新](UNIFIED_PRODUCT_BUILD.md) 为准；下文的独立岛托盘和复用旧二进制仅是历史证据。

用户要求元枢与超级灵动岛作为一个应用使用，解决整合运行时右下角出现两个图标的问题。

本批沿用两项目现有集成草稿：Core 基线 `e5796b84469a6b9b051e457c6e94de1b0cbce213`，Island 基线 `36df1f47287227e74b50f1335502b718850df9bb`。保留当前未提交修改、原配置、会话和语音模型，不迁移数据库，不改授权边界。

## 实现范围

- DesktopClient 统一拥有“元枢”托盘；菜单提供元枢管理、灵动岛操作面板、原任务与设置、灵动岛设置和退出。
- Island 作为元枢组件运行时不注册独立托盘。独立开发启动仍保留原托盘。
- 灵动岛设置使用单实例激活参数 `--assistant-settings`，仅打开已有组件的面板；没有现有实例时直接退出，不能生成失去父进程管理的独立岛。
- 元枢退出仍停止语音、回收自己启动的 Island 并关闭 Host；组件失联仍进入可见恢复入口。
- 两边仍是分离的内部组件，共用一个用户入口；不把两个 Git 历史强行重写为一个仓库。
- 交付仅更新 DesktopClient 与 Island；Host 和其他 121 项既有运行文件逐项按上一桌面候选清单复用。当前工作区中 `BoundSearchFocusWait.cs`、`DesktopAutomationServices.cs` 的未交付搜索实验保持原样，但不混入本批交付。清单另记 `retainedRuntimeBaseline`，区分工作区指纹与实际打包来源。

## 验收标准

真实 Release 程序暂停启动，不开麦：系统托盘仅有一个元枢图标；从其菜单打开管理、灵动岛操作与设置；重复打开不创建第二实例；退出后 Client、Host、Island 均结束。另检查独立 Island 托盘保留、无主实例的设置激活不会遗留窗口。测试不得调用真实模型或录音。

## 完成结果（2026-10-19）

- Client 204 项、Island 前端 151 项、Rust 68 项通过，严格 Clippy 和 Release 构建通过。
- Windows 通知区域和隐藏图标区实际枚举：旧桌面版 2 项，最终桌面候选 1 项，唯一图标为元枢。
- 最终包真实菜单依次打开管理、灵动岛操作、灵动岛设置；设置关闭不退出，重复入口复用原来的 Client/Host/Island，麦克风保持关闭。托盘退出后这三个进程及产品托盘图标均归零。
- 无主实例时 `--assistant-settings`、`--show-controls` 均自行退出；独立模式仍有一个 Island 托盘。独立模式原生菜单未暴露 UIA 子项，改用已读取并核对的原生退出命令清理自己的测试实例，不把普通关窗或发送成功当作退出成功。
- 最终候选 `0.7.0-assistant-unified-tray` 共 128 项产物；121 项运行文件与原桌面版逐项哈希一致。重建范围只有 Client 五项文件与 Island EXE，另更新启动脚本。首次包含当前搜索实验的测试包已隔离留存，未切换到用户桌面。
