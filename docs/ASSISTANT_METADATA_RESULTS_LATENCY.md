# 发行资料查询与结果核对提速

## 范围与证据

本批延续 `assistant-search-five-v2` 候选，目标是减少打开网易云并搜索最新发行歌曲的等待，保留真实灵动岛步骤。工作区包含前批未提交修改，不属于新的冻结发行版。

实测及诊断保存在仓库外 `<private-evidence>/assistant-metadata-results-20261017`，不提交用户日志、截图或运行数据。最终交付状态与耗时以该目录最终报告为准，候选实现或离线测试不代表已达到五秒。

## 已定位的等待

- 当前桌面版同机完整对照为 6.347 秒。计时从完整转写指令提交开始，到 Host 完成，未包含麦克风和语音识别，也不包含额外验收工具的独立读回时间。
- 三次独立进程公开发行查询约 0.8 秒；Apple 发行日期核对和网易云收录核对已经并行。只把最后的收录核对移到输入后，对这三次最多仅省约 79 毫秒，不足以支持大幅提速判断。
- 诊断版结果核对观察为：页面未出现、歌曲结果容器未出现、仍未出现、六首实际歌曲可读。并非其他栏目的 Busy 状态误阻塞。四轮读取共约 221 毫秒，三段等待约 619 毫秒。
- 输入前的完整唯一性检查保留。诊断副本和额外独立读回不进入交付程序；后者的耗时不能误计为产品重复扫描。

## 候选变更与边界

1. 对当前目录精确绑定的 `cloudmusic.exe`，在启动已发起后即可开始这次请求的公开发行查询，与可见窗口等待重叠。启动动作先于查询；不通过把桌面操作移到另一个并发任务实现。未知软件和普通搜索沿用原流程。
2. 结果未就绪时，前 1.5 秒使用 75 毫秒检查间隔，之后恢复 200 毫秒。只缩短等待；每次仍核对本次提交的输入、目标窗口、关键词、加载状态、实际歌曲和结果变化。总超时及后续播放/打开的规则不变。

发行资料不是窗口授权。启动失败、目标变化、用户停止时必须取消正在进行的查询，晚到资料不得触发搜索。最新发行不使用持久缓存；原唱收录未证实仍明确说明，也不自动播放可能是翻唱的第一项。

## 验收要求

先分别实测，再以正式候选至少三轮冷启动、一次既有进程热启动检查真实结果和灵动岛四步提示。冷启动指提交前没有网易云进程；不清理 Windows 缓存。结果须同时报告所有试次与范围，不能以最快一次代表稳定耗时。

只有确认候选比当前对照更快，才更新固定桌面入口；原配置、加密凭据、历史和浮窗位置须保留。是否稳定达到约五秒及是否更新，以本批最终报告为准。
