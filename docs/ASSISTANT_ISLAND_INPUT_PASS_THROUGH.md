# 顶部灵动岛遮挡修正

用户报告顶部胶囊挡住浏览器标签，鼠标无法选择网页。本批只修改助手展示与本机窗口输入，不增加桌面操作能力、录音或模型请求。

## 原因与行为

旧版 296×54 逻辑像素透明窗口仍接收鼠标。实际 Windows 命中检查确认：标签高度的胶囊中心命中了 Island 自身（370×68 物理像素，本机 125% 缩放）。透明背景和 CSS 不能代替系统窗口的鼠标穿透。

整合模式现在默认是 224×28 状态条，顶部间距为 0。说话、执行和需要确认时展开到 480×330，顶部间距为 96；尺寸/间距均为逻辑像素。自动展示不激活窗口，鼠标可穿过，显示状态不伪装成可点击按钮。

Ctrl+Alt+空格、Island 托盘或再次打开桌面元枢进入操作面板。只有这时面板接收鼠标并显示原有开始/暂停、停止、管理、记忆、退出按钮。收起、Esc 或失焦释放交互，不停止麦克风。手动操作期间结果计时器不收起面板；释放时仍需展示的转写、执行、确认文字继续显示。

快捷键冲突不覆盖其他软件快捷键；界面提示从托盘打开。显式激活参数只允许交给已有实例，不会在原子进程已退出时启动孤立助手。独立 Island 模式保持原交互。

## 边界

原始语音最终文本仍等待实际展开及两帧展示回执才提交 Host。SessionCoordinator、原操作授权和逐次确认不变。窗口失联/隐藏仍停止麦克风，不重放未展示指令。用户运行数据沿用原目录，凭据不读取、不复制，保留既有开发修改。

这是两个工作区现有开发候选的修正，不是干净源码冻结版或干净机安装。真实麦克风与语音音色仍由真人验收；使用受控语音/模型的窗口测试不替代真人测试。

真实 Release Tauri + WPF Client + Host 联测 `island-input-final-2.log` 19 项通过，正常退出并清理临时目录。受控监听器/播报/模型，无实际录音或模型调用。Windows `WindowFromPoint` 与实际样式证明 compact 不命中 Island，自动展开命中自建底层测试窗口；手动面板命中 Island；全局键盘输入实际打开面板；切换自建窗口释放且不抢回，收起还原原前台。检查没有操作用户的浏览器或移动指针。语音联测覆盖加载 3.5 秒不阻断可见回执、逐步转写、精确最终回执先于单次提交、结果收起、管理返回、暂停/重启及隐藏后停止且不重放。
