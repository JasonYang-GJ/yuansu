# 自然口语指令被误当成聊天的修复（2026-10-11 开发候选）

用户截图的最终转写为“桌面上的网易云然后搜索周杰伦最新的歌”。此前该句进入 Conversation，模型只解释方案，没有执行。修复继续沿用原 SessionCoordinator、应用目录和一次授权作用域，不增加另一套任务状态，也不让模型决定操作权限。

## 原因与修复

- 省略“打开”的本机目标加顺序搜索未被识别。现在支持这类完整指令，以及有限重复的“给我”等口语前缀。
- “打开桌面上的某软件，并搜索……”被桌面文件规则吞成完整文件名。现在用明确序列边界区分，仍保留引用文件名、有扩展名的歧义文件名和明确文件请求的原路径。
- 应用目录未处理“桌面上的”等修饰语。现在先匹配完整注册名，再处理通用桌面修饰语、已有简称和唯一匹配；网易云、抖音、Blender、微信及其它登记应用使用同一规则。不存在或歧义不擅自选择、不退回聊天。
- “微信搜索助手”等完整注册软件名仍优先于把名称拆成搜索请求；重复口语前缀在两种解析入口保持一致。
- 实机首次启动另外暴露标题变化和搜索语义延迟。原生搜索驱动只在输入之前重新验证本次打开的 HWND、PID、启动时间、程序身份及前台，再刷新标题；不放宽输入过程的严格窗口校验。
- 网易云适配器先只读等待同一原生搜索输入连续两次可靠可用；其它软件原评分逻辑不变。占位文字变化不影响原生身份，重复代理字段冲突仍拒绝。45 秒预算限制启动后续探测，正在执行的同步 UIA/COM 调用无法被硬性截断；返回后必须再次检查取消和窗口身份。
- 写入或提交失败不重试。没有结果证据时仍准确报告尚未验证，而不是声称成功或没有结果。

## 验证与真实边界

1. 原句及同类抖音、Blender、重复口语、完整桌面句式的语言测试先出现 6 项失败：Conversation 或 OpenFile；修复后通过。补充控制字符和完整文件名歧义回归也先失败后通过。
2. 真实 IPC 和 SessionCoordinator 回归确认：Voice 进入精确绑定的 ApplicationSearch；Text 保留确认边界；普通聊天服务调用为零。否定、如何、假设、引述不执行；缺查询、应用不存在及歧义明确失败。
3. 相关 Release 测试：AI.Core 251、Skills.Windows 388、DesktopHost 463，合计 1,102 项通过。属于自动回归，不等同于真人语音验收。
4. 首次实机冷启动记录保留：原先出现 `window_identity_changed`；修复标题后出现 `desktop_search_candidate_ambiguous`。只读探测证实只有一个输入框，但其独立搜索语义在启动后逐步可用；探测没有写入或提交。
