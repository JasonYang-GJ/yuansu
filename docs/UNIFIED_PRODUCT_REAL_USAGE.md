## 修复

1. **待命唤醒依赖不存在的汉字。** 当前普通中文识别模型词表没有“枢”，旧逻辑却要求最终文字严格等于“元枢”。有效真人诊断实际得到完整的“元书”和“你好袁叔”。最终方案只在待命时将完整的“元枢/元书/原书/袁叔/袁书”及对应“你好”形式归为唤醒词；普通对话文字不替换，空文字、“元素”、前后附加内容和动作句均不唤醒。
2. **新资料的首条语音不自动朗读。** 首次提交前没有 Session，原播报资格直接为空。现先绑定请求、Host 实例和监听代际，再由这一次 Host 回执绑定 Session/Turn；停止、换话题、迟到回执和重启不能恢复已撤销资格。隔离真实 Host/IPC/WPF 回归先失败、修复后通过，模拟识别器及声音输出不计真人证据。
3. **系统记事本跳转到商店版后被误拒绝。** 保留已授权的准确系统入口，额外核对 Windows 提供的微软记事本包身份、应用 ID、完整包名和对应完整可执行路径；不按名称放行，不变更预期目标。修复前红例复现，修复后 153 项受影响检查通过，包含假路径、假包名、身份变化与取消；R10 安装版的实际操作也已通过。

唤醒分支只改变本地接收模式，不提交 Host 请求、不调用在线模型、不执行动作。原始文字和规范唤醒词都受回声检查；进入过渡状态及前后识别重置继续拒绝同段重放、旧识别代际与显式停止后的回调。

本批尝试过额外声学唤醒组件，但真人复测未通过，已从最终源码撤回，连同其专用原生接口、音频缓存、词表和健康约束一并移除；用户本机模型文件不删除。最终方案不改变原 ASR 端点，不新增麦克风流或模型分发要求。

## 修复前后回归

最终同音门禁测试先出现 9 个预期失败，修复后 23 项全部通过。完整真实 Host/IPC/WPF 语音 Harness 通过，覆盖长短别名只唤醒、同段重复不提交、普通请求仍经原话题、播放中及播放后的同音回声、旧音频和停止后迟到事件；识别、模型和播报使用测试替身，不计真人通过。

R9 的整段合成音频曾通过，但按真实 80ms 分块和不同开口时机重放时，102 组出现 52 组漏检。进一步实验还发现空文字加短后缀的误唤醒，因此没有继续把声学实验带入最终产品。有效真人诊断确认两个完整同音文字均通过候选检查，却没有声学命中。这些失败完整保留，不能被后续成功覆盖。

第一次外部真人诊断因倒计时早于麦克风就绪 3.65 秒而无有效发音证据；修正为加载期间明确等待、实际就绪后再计时后，第二次取得了上述识别结果。两次均由用户在可见窗口点击，自动停止，不保存音频、不联网；仅保留短测试文字、音量及判定元数据。

R10 最后实测先确认了声音回答，但“休息”被按普通对话接收，不能据此断言当时已经待命。随后明确观察到待命状态；用户对短词唤醒的反馈与工具观察未同步，因此没有把该次计为完整状态证据。最后单独使用“你好元枢”，同时取得界面三步状态变化、用户听到准确本地回应、无新增 Turn/模型调用的闭环。短词的每次成功率、不同口音及环境仍无测量结论。
