# 网易云搜索准备与结果加载调查

本批用户目标：继续缩短冷启动搜索，争取稳定约五秒；保留灵动岛真实步骤，实测确认更快后才替换桌面版本。

本批是内部候选调查，不是版本冻结或已发布声明。已有桌面基线为 `0.7.0-assistant-metadata-results`。全部运行证据在仓库外 `<private-evidence>/assistant-native-ready-20261017`；最终结果和入口状态以该目录 `实测结果.md` 为准。

## 已查明及尚不能归因的部分

- 默认诊断中发行资料在窗口就绪前已返回；准备阶段约 1.7 秒。第一次 UIA Edit 可见仍不等于原生搜索语义、可写状态已经就绪。
- 结果核对沿用本次提交的输入回执，没有重新执行完整输入查找。历史成功冷启动的结果阶段约 0.9–1.1 秒；详细诊断曾观察到搜索页或结果容器尚未出现，不能靠提前显示完成消除等待。
- 当前基线同批出现一次 15.321 秒完成，另一次未确认焦点而中止。10 秒以上的搜索阶段尚未捕获完整分段证据，不能把其原因全部归于焦点等待。
- 一次详细成功诊断中，UIA SetFocus 不支持，原生 accSelect 返回后未立即确认焦点；随后既有 Invoke 返回，约 0.2 秒后才确认焦点。原有六次回读并不足以保证所有冷启动都及时收到回执。

## 已排除的实验

- 在 UIA 前独立读取原生控件 2.5 秒没有更早找到搜索框，不改成纯原生输入驱动。
- 将只读顶层初始化的 Edit 查询换为 Document 导致 45 秒准备超时，未采用。
- 对重复顶层初始化设 250 毫秒间隔，一次完成 6.64 秒，另一次中止，未证明稳定改善，实验源码与产物保留在仓库外，产品改动已撤回。
- 在原生 accSelect 后额外等 250 毫秒并未取得焦点，仍需原有 Invoke，不引入此额外等待。
- 不为提速省略非输入节点的身份、所属窗口、完整孩子及循环检查；也不缓存旧发行资料或以未完成的页面作为完成结果。

## 保留的候选修复

只修复现有聚焦动作的回执处理：两次备用动作前的完整快照已确认焦点时不再 Invoke；真正 Invoke 后只读等待同一控件，使用一个 1 秒总预算，焦点到达即返回。它不重复聚焦、输入或回车，身份/前台变化与取消立即停止，慢同步读取不重置预算。这是稳定性修复，不预先宣称可减少冷启动秒数。

完整唯一性、当前控件安全状态、精确写回、单次 Enter、输入回执与真实结果页核验保持原边界。灵动岛仍显示真实打开、发行资料、搜索、结果核对和完成状态。

## 验收口径

冷启动指提交完整转写文字前没有网易云进程；不清空 Windows 文件缓存。计时从 Host 收到完整文字到实际搜索及结果核对完成，不包含真人说话/语音识别，也不把随后独立结果读回时间算入产品耗时。

保留所有失败尝试，不将失败终止时间作为速度成绩；当前成功对照全部进入统计，包括慢尾。候选须通过离线回归、真实冷启动与热启动、独立结果读回和真实灵动岛观察。未证明更快不激活桌面快捷方式。此次不验收麦克风/ASR、截图、播放、全球最新或原唱可用性。
