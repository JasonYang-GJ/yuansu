# 悬浮助手入口恢复

2026-09-22，用户明确要求手动打开元枢后显示精灵球并直接语音对话，管理页仅按需使用。本批沿用现有开发草稿和数据，不回退旧安装程序，不改变正式冻结版本。

## 原因与范围

此前桌面修复入口指向 DesktopClient 的 `--show` 管理窗口。真实入口检查得到 1700×1075 的管理界面，未显示小球。早期悬浮程序使用旧架构，不能简单换回旧 EXE，否则会丢掉近期应用识别、会话协调和语音修复。

本批在当前 Client 增加 AssistantOrbWindow，仅显示状态、简短回复和控制入口。它使用元枢现有原创图标，通过现有 MainWindow 请求同一 Host SessionCoordinator，不建立第二套对话/任务，也不直接执行动作、读取密钥或开启屏幕捕获。

## 启动与关闭

- 手动无参数或 `--assistant` 启动：先显示小球，再初始化会话与语音。按用户本次明确要求，手动启动就是进入本次语音对话；小球持续显示状态，点击小球暂停，退出关闭麦克风。
- `--show` 保留显式管理入口，不自动开麦；`--background` 即便与其他参数冲突也不开麦、不激活已有窗口；`--paused` 提供可见但不开麦的预览入口。
- 重复启动与托盘打开只显示已有小球，不撤销用户的暂停选择。显式管理激活信号仍打开管理窗口。
- 隐藏的 MainWindow 通过幂等初始化加载当前 Session、更新循环和刷新定时器；显示/收起管理页不会重复初始化监听或会话。
- 管理窗口的关闭和“返回悬浮球”回到仍可见的小球；小球退出先撤销语音/播报和本地排队输入，再停止本机服务。原生清理与 Host 退出各有 5 秒上限，失败不能永久卡住 Client 退出。
- 文件、项目、单窗口读取和其他需要确认的请求仍显示“查看确认”，进入原管理卡片处理；不自动同意，不扩大动作范围。

只用测试文字渲染小球自己的 WPF 视觉树检查普通/待确认状态；没有截图用户桌面。图标修正为原高分辨率 PNG，避免 ICO 小帧被放大。当前拖动范围为主屏工作区；没有宣称跨屏、唤醒词待命或任意软件任意操作已实现。
