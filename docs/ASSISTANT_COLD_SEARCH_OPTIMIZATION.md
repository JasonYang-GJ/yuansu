## 证据与待验证假设

2026-10-13 两次实测均在完成前遇到前台窗口变化，并以 `application_search_window_changed` 停止，没有输入或提交。一次隔离 Host 尝试、一次直接执行层分段计时；后者仅定位耗时，不替代 Host 授权路径验收。

分段记录中发行查询约 3.647 秒，两次完整搜索发现分别约 3.798 秒和 14.750 秒。窗口变化可能影响后台应用响应，不能由这两次失败记录认定正常冷启动的准确瓶颈或宣称加速。原始失败证据继续保留。

代码已确认唯一输入证明只使用每个节点的身份、窗口归属、角色和完整子节点列表，但此前每个节点还读取并解析属性、读取状态。本批已移除该证明路径的多余读取；实际延迟收益仍须原应用测量。此前纯原生就绪替代完整 UIA 初始化的失败方案不重做，详情见 [上一批探索记录](ASSISTANT_LIVE_PROGRESS.md)。

## 实现与验收约定

- 轻量读取仍核对每个节点的非零 IA2 身份、所属窗口和角色；遍历前后复核根身份与窗口，不缓存到下一次请求。
- 完整子节点枚举、数量一致、深度/节点数上限、循环拒绝和所有输入的计数保留。隐藏、禁用或密码输入不能通过忽略状态而被排除在唯一性证明之外。
- 原完整 `ReadNode` 仍用于搜索语义和结果读取；最终候选的属性、边界、密码/只读、焦点和值等检查保持。唯一输入证明不等于有权输入。
- UI Automation 初始化、完整发现回退、两次稳定就绪检查以及输入前再验证保持。停止或切换目标时仍停止操作。
- 离线测试使用假控件和隔离数据；排除会启动或激活真实窗口的测试。调用计数只能说明省去多少读取，不能换算为实际提速秒数。
- 最终实测需通过隔离 Host 提交原指令，分别记录首次前台、完成搜索、结果读回与真实步骤显示；不得把直接执行层探针或合成阶段当作完整验收。
