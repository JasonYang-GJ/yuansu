# 语音状态与运行配置修复

2026-09-22，用户提供启动语音弹窗及“AI 服务尚未配置”的真实截图，授权修复。沿用当前开发草稿，不变更正式冻结版本或安装注册。

## 已确认原因

- 桌面入口此前切到了独立开发候选的数据目录，该目录没有 AI 设置或凭据，默认选中未配置的服务。原用户目录仍有千问设置和 Windows 当前用户加密保护的凭据，迁移时未接上。
- 语音每次刷新只根据模型/麦克风存在性和 IsListening 推断状态；只要没有监听便显示“正在启动”，覆盖启动失败或已停止状态，不能作为真实启动证据。
- 外部 VBS 启动器添加了语音同意弹窗，并通过空模型目录表示不同意。它混淆了用户选择与模型缺失，也让界面反馈难以理解。

## 本批范围

恢复原来的模型路由和加密凭据，保留源文件和现有候选会话。外部启动器不再询问语音或伪造模型缺失，首页显式开始/停止按钮管理本次语音授权。启动、停止、失败与重试必须显示真实状态，停止和关闭不得在模型迟到加载后重新开始录音。不添加隐式麦克风采集、自动重试请求或 Provider 回退。

## 配置恢复证据

恢复前通过真实 Host 查询：当前路由为 DeepSeek，API 配置 Missing；数据库近期 Voice 会话均因 configuration 失败。原目录与迁移目录的千问设置及密文逐字节一致。仅在目标文件不存在时复制原设置和密文，不读取明文、不覆盖源文件、不将凭据写入仓库。

恢复后真实 Host 选中原 qwen / qwen3.7-plus，配置状态 Configured，健康检查 Healthy；独立测试话题的一次最小请求返回“已连接。”且 Turn 为 Completed。没有把测试结果写回用户旧失败 Turn，也没有重发历史请求。

## 语音修复与验收

首页新增显式开始/停止，Loaded 不自动调用 Start。VoiceSessionController 保存当前语音状态，刷新不会推断成虚假的启动中。30 秒启动超时撤销授权；原生模型加载无法中断时继续显示正在取消，后台等待清理，不允许并发重试。窗口关闭开始即撤销许可，即使还在等待其他功能关闭确认。

停止与重开之间用监听代际拒绝旧的界面队列回调；原生层校验当前麦克风对象及本轮取消状态，在发送结果时再次核对，阻止迟到文本执行动作。停止清理失败保留设备引用，界面要求关闭应用，禁止再次开启；普通启动失败且清理成功仍可重试。独立只读复核发现的上述边界均已修正，无遗留阻断项。

- 最终相关 Release 回归：DesktopClient 91/91、Voice 43/43、Release 窗口与假监听器的显式按钮流程 1/1，共 135/135。覆盖首次不启动、重复启停、失败/停止后的刷新、启动中取消、超时、关闭、设备停止、清理失败以及旧回调。
- 本机真实识别器只创建并释放，模型完整，约 3.1 秒加载成功，没有调用麦克风采集。
- 配对发布候选 `0.7.0-voice-config-repair`。桌面快捷方式已备份并更新；从真实快捷方式启动时没有外部语音弹窗，首页“语音未开启”、开始按钮可用、停止按钮禁用，窗口响应正常。等待刷新和完成聊天后仍保持该状态。

真人语音输入与设备实际故障仍需要用户在首页主动开始后验收，以上模型加载和假监听器测试不能替代真人讲话。没有自动重发失败的历史请求；没有截图或采集音频，未添加后台开麦或开机启动。当前仍为开发修复候选，不是新的正式冻结发布。

## 后续实际反馈：有文字、没有语音回复

用户在上述候选中主动开启语音后，确认能得到文字回复，但没有声音。这补充确认了真人输入到文字回复的链路，不能据此认定语音播报已完成验收。此前结论中的真人输入待验收由本次反馈更新。

代码确认：原来只有“朗读结果”按钮调用本地语音合成，Voice Turn 完成没有自动调用。补充修复将本窗口、本轮显式监听提交的 Voice Turn 与播报资格关联，完成或失败反馈只播放一次；该关联不持久化，不回放历史，不改变 Host SessionCoordinator 的请求执行及权限。
